部署与使用说明

  

    
安全警告：管理代理虽然不直接开放 9180，但仍是高权限 Admin API 入口。CORS 只限制浏览器，不是身份认证或网络访问控制。请使用 HTTPS、强 Admin Key、可信网络/VPN、访问审计和最小权限；TOKEN 保存在浏览器本地，只在可信设备使用。

    
1. 部署单文件页面

    
  1. OSS：上传 index.html，为 OSS 绑定自己的域名并配置 HTTPS，按实际环境配置对象访问权限。确保浏览器获得 text/html; charset=utf-8，且响应不会强制作为附件下载。
    2. 
      
  2. Nginx 或其他 Web 服务器：将文件放入静态目录，配置 HTTPS 和 HTML 内容类型即可；无需构建或安装依赖。
    3. 
      
  3. 通过 APISIX 代理 OSS：可使用下面的静态页面路由示例，仅开放 GET、HEAD 并限定入口路径。

    
以下域名、地址和 IP 范围均为示例，使用前必须替换。OSS 上游域名应已绑定存储服务且证书有效；核对 DNS、Host、TLS SNI 与证书验证。若启用缓存，请控制 TTL 或发布时清理缓存，以免旧页面继续生效。

    
静态页面代理路由示例

    
{
  "name": "APISIX-UI",
  "hosts": ["api6.sample.com"],
  "uris": ["/", "/index.html"],
  "methods": ["GET", "HEAD"],
  "plugins": {
    "proxy-rewrite": {
      "uri": "/apisix/index.html"
    },
    "response-rewrite": {
      "headers": {
        "remove": ["Content-Disposition"],
        "set": { "Content-Type": "text/html; charset=utf-8" }
      }
    }
  },
  "upstream": {
    "type": "roundrobin",
    "scheme": "https",
    "pass_host": "node",
    "tls": { "verify": true },
    "nodes": [
      { "host": "oss-origin.sample.com", "port": 443, "weight": 1 }
    ]
  }
}

    
2. 保护 Admin API

    
重要：9180 只监听容器内本机，初始化或修改默认路由时进入 APISIX 容器执行。以下 127.0.0.1 代理方案要求代理进程与 Admin API 在同一网络命名空间；分离部署时必须按实际拓扑重新设计受控网络。不要把 9180 发布到宿主机或公网。

    
管理代理可能向 Admin API 传递客户端真实 IP；若 allow_admin 只允许回环地址，在部分真实 IP 配置下外部代理请求会被拒绝。以下示例放开 IPv4 的 allow_admin，由代理路由的 ip-restriction 限制实际客户端来源；同时必须保持 9180 只监听本机，并确保只有可信的本机进程能够访问它。IPv6 和不同网络拓扑需单独评估。

    
防护责任变化：allow_admin: 0.0.0.0/0 不再按 IPv4 来源限制 Admin API。能直接连接本机 9180 的其他进程会绕过代理路由的 IP 限制；必须依靠本机监听、容器及主机隔离、Admin Key 和可信进程管理保护该端口。切勿使用此配置将 9180 暴露给外部。

    
在 config.yaml 中示例配置如下，并按部署方式确认未将 9180 映射到外部。保留安全的 Admin Key 配置；配置更改后按 APISIX 部署方式生效。

    
deployment:
  admin:
    enable_admin_cors: false
    admin_api_version: v3
    admin_listen:
      ip: 127.0.0.1
      port: 9180
    allow_admin:
      - 0.0.0.0/0

    
使用 APISIX 业务端口代理时，为管理域名配置 TLS 证书。IP 白名单仅为示例，必须替换为实际可信来源；APISIX 位于反向代理之后时，只能信任已明确配置的前置代理及其客户端 IP 头。

    
Admin API 代理路由示例

    
{
  "name": "apisix-admin-api",
  "hosts": ["mgt.sample.com"],
  "uris": ["/apisix-admin/*"],
  "priority": 101,
  "plugins": {
    "cors": {
      "allow_credential": false,
      "allow_headers": "Content-Type,X-API-KEY",
      "allow_methods": "GET,POST,PUT,PATCH,DELETE,OPTIONS",
      "allow_origins": "https://api6.sample.com",
      "max_age": 86400
    },
    "ip-restriction": {
      "message": "Access denied",
      "whitelist": ["192.0.2.0/24"]
    },
    "proxy-rewrite": {
      "regex_uri": ["^/apisix-admin/(.*)", "/$1"]
    }
  },
  "upstream": {
    "type": "roundrobin",
    "scheme": "http",
    "pass_host": "pass",
    "nodes": [
      { "host": "127.0.0.1", "port": 9180, "weight": 1 }
    ]
  }
}

    
安全边界：代理路由允许访问 Admin API，必须保留 Admin Key 校验并限制来源；切勿缓存管理 API 响应。CORS 的来源必须与页面实际协议、域名、端口一致。APISIX 的 CORS 插件可能直接响应 OPTIONS 预检；预检成功不代表实际请求通过了 IP 或鉴权限制。额外启用 key-auth 等认证时，当前页面只发送 X-API-KEY，若需要其他凭据，须先确认兼容性。

    
3. 配置连接与验证

    
  1. 页面新增连接时，管理 API 地址填写 https://mgt.sample.com/apisix-admin，并填写 Admin Key。页面自动追加 /apisix/admin；代理会移除 /apisix-admin 前缀。
    2. 
      
  2. 预期请求示例：/apisix-admin/apisix/admin/routes → /apisix/admin/routes。如果 HTTPS 使用非默认端口，地址中也要填写端口。
    3. 
      
  3. 从授权网络验证静态页面、CORS 预检，以及 GET、创建、更新、上下线和删除操作；从未授权网络验证访问被拒绝。配置失败时检查 DNS、证书、白名单、真实客户端 IP 和浏览器网络错误。

    
使用标准 APISIX Admin API v3 分页响应；页面路径和鉴权方式不因部署方式改变。以上示例需结合实际 APISIX 版本、网络拓扑、TLS 和插件配置验证后使用。
